코딩 규칙 및 지침

1. 일반원칙
*KISS (Keep It Simple, Stupid):* 분리 추상화를 피하고 명확한 코드를 작성하라.
*DRY (Don't Repeat Yourself):* 반복되는 형태는 맞춤형 분리(`hooks/`)이나 비행편(`utils/`)로 분리하라.
*Functional Components:* 모든 구성요소는 React Functional Component로 작성하며 Hooks를 사용하라.

2. 파일 구조
`/src/comComponents`: UI 구성 요소(예: `Column.tsx`, `TaskCard.tsx`)
`/src/hooks`: 원천 분리 (e.g., `useKanban.ts`, `useTheme.ts`)
`/src/types`: TypeScript 인터페이스 정의(예: `types.ts`)
*규칙:* 하나의 파일에는 하나의 구성요소만 있어야 합니다. (100줄이 없으면 분리하려고 합니다)

3. 명명 규칙
*구성 요소:* PascalCase(예: `TaskCard`)
*함수/변수:* camelCase(예: `handleDragEnd`, `isLoading`)
*유형/인터페이스:* 명시적인 이름 지정이 있는 PascalCase(예: `Task`, `ColumnStatus`)

4. 스타일링(Tailwind CSS)
인라인 스타일(`style={{}}`) 사용 방지. 활동적인 조직화 Tailwind 전투기 클래스 구성(`clsx` 또는 `tailwind-merge`)을 사용하는 것입니다.
색상은 하드코딩하지 말고 Tailwind의 시맨틱 색상(bg-primary, text-muted 등)나 기본 기둥을 뒤집는 것입니다.

5. 상태 관리 및 논리
`useEffect` 사용을 방해하고 이벤트 핸들러 내에서 동작을 처리하라.
비즈니스 부분(데이터베이스, 드래그 꺼내기 등)은 UI 구성요소 내부에 두지 않고 `hooks`로 분리하라.

6. 오류 처리
드래그 앤 앤 드롭 시 UI가 반대 방향으로 원상복구하는 경우도 있습니다.
`localStorage` 접근 시 이벤트 처리를 포함하라(try-catch).

7. CDN(인터넷)에서 수신을 대신하여, 방문자 내부에 알림을 포함하여 오프라인 환경을 맞춰야 합니다.
