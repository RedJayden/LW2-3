# 재기동 후 모드 전환 무반응 및 오브젝트 모드 전환 뷰포트 왜곡 해결 계획서 (개정본 V3)

## 1. 개요 및 원인 분석

### 1.1. 현상 및 사용자 문제 제기
1. **재기동 후 스캐너 모드 이동 후 Fit to Camera 미작동**:
   - 기기를 오브젝트 위치에 둔 채 앱을 종료하고 재시작하면 UI는 기본 스캐너 모드 상태가 됩니다.
   - 스캐너 물리 중심부로 기기를 이동시키기 위해 상단 Scanner 모드 버튼을 클릭하면, 하드웨어는 정상적으로 (0, 0)으로 이동 완료하지만 **Fit to Camera가 작동하지 않고** 전체 뷰(Fit to Workarea) 상태에서 멈춥니다.
   - 하지만 이후 수동으로 모드를 서로 전환(오브젝트 ↔ 스캐너)하면 스캐너 모드 Fit to Camera가 정상 작동합니다.
2. **오브젝트 모드 완료 시 카메라 영역 왜곡 및 튕김 현상**:
   - 오브젝트 모드로 전환 완료 시, 찰나의 순간에 카메라 뷰 영상이 정확히 보인 직후, 스테이지 센터 기준으로 카메라 뷰 영역(옵셋 크기만큼)이 시프트되거나 비정상적으로 거대해져 엉뚱한 위치를 보이며 화면이 텅 비는 오류가 발생합니다.

### 1.2. 근본 원인 분석
1. **재기동 시 하드웨어 좌표 수신 타이밍 이슈 (2-Step 가드 오작동)**:
   - 앱이 처음 켜질 때, 백엔드로부터 실제 하드웨어 위치 데이터(`positions`)가 정상적으로 수신되기 이전(기본값 `X = 0, Y = 0` 상태)에 `RecipeCanvas.tsx` 의 `useEffect` (Restoration & Auto-Initialization Logic)가 먼저 실행됩니다.
   - 이 시점에 `viewMode`는 `scanner`이고, 타겟 좌표 역시 `(0, 0)` 이므로 기기가 타겟에 있는 것으로 판정(`isAtTargetPos = true`)되어 즉시 `Fit to Camera`가 수행되고 `isPendingAutoCameraFitRef.current` 가 `false`로 셋업됩니다.
   - 그 직후 실제 하드웨어 위치 `(13.282, -78.169)`가 수신되지만, Restoration 훅은 의존성에 `positions`가 없으므로 다시 실행되지 않으며, `isPending`은 이미 `false` 상태라 2-step 이동 대기 흐름을 타지 못하게 됩니다.
   - 결과적으로 기기가 실제 목적지(스캐너 중심 0,0)에 도달해도 2-Step 피팅 타이머가 돌지 않는 것입니다.
2. **좌표 동기화 공식의 불일치 (`userPan` 시프트 누적 버그)**:
   - V2 개정본을 통해 `RecipeCanvas.tsx`(`fitCameraArea`)와 `CanvasBackground.tsx`(`updateAll`)에서는 오프셋 보정 상수를 완전히 배제(`mx = 0, my = 0`)하도록 정렬했습니다.
   - 하지만 캔버스의 눈금자와 드로잉 뷰포트를 실시간 동기화하는 **`useGridSystem.ts` 의 `updateRuler` 훅 내부**에서는 여전히 `recipeCenter`로부터 실제 오프셋(`mx = 13.282, my = -78.169`)을 가져와 연산에 사용하고 있었습니다.
   - 이로 인해 `fitCameraArea` 가 완료되는 즉시 `updateRuler` 가 실행되면서, `userPan` 변수를 비정상적으로 큰 값(`-30,000` 이상)으로 덮어쓰게 되고, 이 거대한 `userPan`이 뷰포트와 영상 투영 레이어를 화면 밖으로 날려버리는 좌표 왜곡 현상을 초래했습니다.

## 2. 해결 방안 (Three of Thought 교차 검증)

- **Strategy A (초기 기동 시 positions 싱크 감지 가드 도입 - 채택)**:
  - `RecipeCanvas.tsx` 내부에서 백엔드로부터 최초 positions 수신을 감지하는 `isFirstPositionsSynced` 로컬 상태와 안전용 1초 타임아웃 가드를 도입합니다.
  - 최초 하드웨어 좌표가 수신될 때까지 뷰포트 복원 및 초기화 로직을 대기시켜, 실제 위치가 `(13.282, -78.169)` 인 상태에서 정상적인 2-Step 감지 흐름(`isPendingAutoCameraFitRef.current = true`)을 타도록 확실히 차단합니다.
- **Strategy B (Ruler 오프셋 연산 동기화 - 채택)**:
  - `useGridSystem.ts` 의 `updateRuler` 내부에서도 카메라 오프셋 보정 연산을 완전히 배제(`mx = 0, my = 0`)하도록 수정하여 `RecipeCanvas`, `CanvasBackground` 와 기하학 수식을 100% 일치시킵니다.
  - 이로써 `userPan`에 엉뚱한 시프트 값이 누적되는 현상을 원천 방지합니다.

3. **빌드 안정성 확인**:
