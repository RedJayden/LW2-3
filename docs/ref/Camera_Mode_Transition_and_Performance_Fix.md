# 📸 스캐너 및 오브젝트 카메라 모드 전환 동기화 및 캔버스 패닝 렌더링 최적화 종합 리포트

본 문서는 스캐너(Scanner)와 오브젝트(Object) 모드 간의 전환 시 발생하던 Fit to Camera(자동 줌인) 실패 버그 및 캔버스 패닝 시 발생하던 심각한 렌더링 지연(Lag) 현상에 대한 원인 분석과 최종 수정 사항을 기록합니다.

---

## 1. 캔버스 패닝(Panning) 렌더링 지연(Lag) 완전 해결

### 🛑 이슈 내용
- 캔버스 안에서 마우스 휠이나 패닝 툴을 이용해 화면을 드래그할 때 뚝뚝 끊기는 극심한 버벅임이 발생.
- 이전(2.14 패치)에 한 번 잡았던 버그였으나 십자선/그리드 시스템 개편 과정에서 부활함.

### 🔍 원인 분석
- `useGridSystem.ts` 훅 내부에 `useCanvasStore(s => s.pan)` 이라는 **전역 상태 구독 로직**이 재삽입되어 있었습니다.
- 마우스가 1픽셀 움직일 때마다 Ruler(눈금자) 좌표 갱신을 위해 `pan` 상태가 초당 60회씩 갱신되는데, 메인 캔버스(`RecipeCanvas.tsx`)가 이 훅을 사용하면서 수천 줄짜리 메인 캔버스 컴포넌트 전체가 초당 60회 강제 리렌더링되는 치명적 병목이 발생했습니다.

### 💡 최종 수정 결과
- `useGridSystem.ts` 내부의 불필요한 `pan` 구독을 완전히 제거했습니다 (`getState().setPan` 등으로 우회).
- `RecipeCanvas.tsx`에서도 불필요한 `panOffset` 반환값 비구조화 할당을 지웠습니다.
- **결과**: React 리렌더링 체인을 끊어내어 마우스 드래그 시 Fabric.js 렌더링 엔진만 부드럽게 가속되도록 60FPS 패닝 성능을 원상 복구했습니다.

## 2. 모드 전환 시 "Fit to Camera" 미작동 (타겟 좌표 매핑 오류) 해결

### 🛑 이슈 내용
- 스캐너 -> 오브젝트로 모드 전환 시에는 화면이 정상적으로 타겟에 줌인되나, 반대로 **오브젝트 -> 스캐너로 전환 시 타겟에 도착했음에도 화면이 전혀 엉뚱한 비율과 위치에 머물러 있는 현상** 발생.

### 🔍 원인 분석
1. **타겟 좌표 하드코딩의 맹점**:
   - 모드 전환 시 기계(스테이지)가 목적지에 완전히 도달했는지를 판별하기 위해, 프론트엔드가 타겟 좌표를 비교해야 했습니다.
   - 이전 코드에서는 스캐너 모드로 전환할 때 타겟 좌표(`tgtX`, `tgtY`)를 무조건 `(0, 0)`으로 하드코딩했습니다.
   - 하지만 **실제 기계의 이동 목표 지점은 절대 좌표 (0,0)이 아니라, Parameter 페이지(Mirror Configuration)에 설정된 `Offset X, Y` 값**이었습니다.
   - 따라서 기계는 올바른 위치(Offset 좌표)에 멈췄으나, 프론트엔드는 스테이지가 (0,0)에 오지 않았다고 착각하여 무한 대기하며 Fit to Camera 로직을 가동하지 않았습니다.
2. **고해상도 배율 오연산 (Scale 하드코딩)**:
   - 렌더링 뷰포트 크기와 패닝 제한 범위(`panMinX`, `panMaxX` 등)를 계산할 때, 현재 렌즈 배율(`activePxPerMm`)이 아닌 스캐너 고정 배율(`baseScale` = 1000)을 곱하는 오류 로직이 섞여 있었습니다. 이로 인해 오브젝트 모드(예: 5427 px/mm)에서 화면 밖으로 튕기는 현상이 함께 동반되었습니다.

### 💡 최종 수정 결과
- **기계적 목표 좌표(Offset X/Y) 완벽 동기화**: `useAppStore`의 `recipeCenter` 상태(Parameter 페이지의 Offset 값을 저장하는 객체)를 직접 읽어와 타겟 좌표로 지정했습니다.
  - Scanner Target: `recipeCenter.scanner.x`, `recipeCenter.scanner.y`
  - Object x20 Target: `recipeCenter.object_x20.x`, `recipeCenter.object_x20.y`
  - Object x50 Target: `recipeCenter.object_x50.x`, `recipeCenter.object_x50.y`
- **안정화 타이머 도입**: 스테이지 위치(`positions.X`, `positions.Y`)가 위의 동적 Offset 목표 위치 반경 0.1mm 이내에 완벽하게 도착(`isAtTarget`)한 직후부터 기계적 안정화 0.5초 대기를 거쳐 Fit to Camera가 발동되도록 수정했습니다.
- **고해상도 배율 연산 원복 (`activePxPerMm`)**: 렌더링 연산에 하드코딩된 `1000` 상수를 완전히 몰아내고, 2.15 패치에서 의도했던 대로 `activePxPerMm` 값을 정확하게 다시 적용하여 좌표 무결성을 달성했습니다.

### ✅ 검증 결과
- 모드 전환 시, 프론트엔드가 기계의 Parameter Offset 값에 맞춰 똑똑하게 이동 완료 시점을 감지하고, 화면이 정확한 비율과 위치로 자동 줌인됩니다. (수동 Offset 값 변경 테스트 대응 완료)
- 빌드(`npm run build`) 무결성 테스트를 통과하였습니다.
