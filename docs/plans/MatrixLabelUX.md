## 1. 현행 구현과 문제 분석

### 1.1 현행 렌더링 (`MatrixRepeater.drawObject()`, `MatrixRepeater.ts:564-574`)

```ts
ctx.translate(dx, dy);
ctx.scale(1 / zoom, 1 / zoom);          // 이후 그리기 단위 = "화면 px"
ctx.font = '11px sans-serif';           // 화면 고정 11px (줌 무관 상수 크기)
ctx.fillStyle = 'rgba(0, 190, 255, 0.95)';   // 레이어색(시안) 텍스트, 배경 없음
ctx.fillText(`(${row},${col}) Z:${absoluteZ.toFixed(3)}`, _srcMinX * zoom, (_srcMinY - 2) * zoom);
```

과거 "확대하면 글자가 사라진다" 버그(폰트 문자열에 `11/zoom` 직접 대입)를 고치면서 **완전 화면 고정(constant screen-size)** 방식을 채택했다. 위치·수치의 정합성은 완성됐으나, 표시 품질 관점의 문제가 남아 있다.

### 1.2 문제점 (3인 관점 정리)

| # | 관점 | 문제 | 근거 |
|---|---|---|---|
| F1 | 시각 위계 | **스케일 괴리**: 도형 선폭·셀 크기는 scene 단위라 줌에 비례해 커지는데 라벨은 항상 11px → 622% 확대 시 셀이 화면을 가득 채워도 라벨은 손톱만 함(실기 스크린샷). 사용자의 주 시선 대상(확대해서 보려는 셀)에 정보가 따라오지 않음 | `:568-569` 고정 11px |
| F2 | 대비/가독성 | **배경 칩 없음 + 레이어색 텍스트**: 시안 텍스트가 ① 시안 도형 선과 겹치고 ② 실시간 카메라 그레이스케일 영상 위에 직접 그려져 밝은 영역에서는 대비가 무너짐. 11px는 밀집 정보의 최소 권장(12px)에도 미달 | `:570` 단색 fillText |

| F4 | 상태 표현 | **활성 셀 무강조**: 셀을 클릭 선택(activeCell)해도 해당 라벨이 다른 셀과 동일 — 편집 중인 셀의 Z 값을 눈으로 추적하기 어려움 | `activeCell` 미사용 |
| F5 | 경계 클리핑 | 라벨이 셀 "위쪽"에 고정 — 최상단 행이 화면/카메라 영역 상단에 붙으면 라벨이 뷰 밖으로 잘림 | `:572` 고정 오프셋 |

### 1.3 업계 레퍼런스 (모던 캔버스 도구의 라벨 관례)

- **Figma/Sketch(측정 라벨)**: 텍스트는 화면 고정 크기지만 **항상 고대비 배경 칩(pill)** 위에 얹음 — 어떤 배경 위에서도 가독 보장. 본 건 F2의 표준 해법.
- **CAD/CAM(LightBurn, KiCad 등)**: 주석·번호는 줌에 **부분 추종**(어느 정도 같이 커지되 상·하한 클램프) 또는 도면 단위 고정 + 최소 화면 크기 보장. "확대했는데 주석이 안 커진다"는 위화감(F1)의 표준 해법은 **클램프형 하이브리드 스케일링**.
- **지도 엔진(Mapbox/Google Maps)**: 줌 레벨에 따라 라벨 **표시 밀도 자체를 조절(LOD)** — 겹칠 라벨은 아예 그리지 않는다. F3의 표준 해법.

## 2. 개선안 (채택 설계)

### 2.1 F1 — 클램프형 줌 추종 크기 (핵심)

라벨 화면 크기를 줌에 따라 키우되 상·하한을 클램프한다:

```
fontScreenPx = clamp(MIN 11, BASE 11 × zoom, MAX 22)
```

- `zoom ≤ 1`: 현행과 동일 11px(축소해도 절대 작아지지 않음 — 기존 "축소 시 소멸" 버그 회귀 없음).
- `zoom 1→2`: 도형과 함께 자연스럽게 커짐(줌 추종의 체감 제공).
- `zoom > 2`: 22px에서 고정(초확대 시 라벨이 화면을 삼키지 않음).
- 구현은 현행 구조 그대로: `ctx.scale(1/zoom)` 이후 단위가 화면 px이므로 `ctx.font = fontScreenPx + 'px ...'`만 계산식으로 교체. 위치 수식(`_srcMinX * zoom` 앵커)은 불변 — MatrixDisplayIssues2 수정과 충돌 없음.

### 2.2 F2 — 고대비 배경 칩 + 텍스트/액센트 분리

- **칩**: 반투명 다크 라운드 사각형(`rgba(17,24,39,0.78)`, radius 4px, 패딩 H6/V3px — 전부 화면 px 단위) 위에 텍스트. 카메라 영상 밝기와 무관하게 대비 보장(다크 테마 UI와 동일 시각 언어).
- **텍스트**: 근백색 `#F1F5F9`(레이어색 텍스트 폐기 — 도형 선과의 동색 겹침 제거).
- **액센트**: 칩 왼쪽에 레이어색(#00BEFF 등, `resolveObjectColorHex` 결과) **색점(dot) 6px** — 어느 레이어의 매트릭스인지 색 정보는 유지하되 가독성과 분리.
- 폭 계산은 `ctx.measureText()` — 문자열+폰트크기를 키로 리피터 내부 Map에 캐시(프레임당 재측정 방지, 라벨 내용은 Z 변동 시에만 변함).

### 2.3 F3 — 표시 밀도 LOD

- 셀 그리드의 **화면상 피치** `pitchScreen = min(xSpacing, ySpacing) × zoom`이 임계(예: 32px) 미만이면 일반 셀 라벨을 생략한다(겹쳐서 읽을 수 없는 라벨은 그리지 않는 것이 정보 전달상 이득 + 성능 보호).
  - 이때도 **(0,0) 셀 라벨 1개는 유지**해 "라벨 기능이 꺼진 게 아니라 축소 때문"임을 알린다(지도 엔진 관례).
- 프레임당 라벨 상한(예: 300개) 가드 — 칩/측정 도입 후에도 100×100 팬/줌 60FPS 유지.

### 2.4 F4 — 활성 셀 강조

- `activeCell` 라벨은 LOD와 무관하게 **항상 표시** + 강조 스타일: 폰트 +2px, 칩 배경 `rgba(0,190,255,0.9)`(레이어색) + 텍스트 다크(`#0B1220`) 반전. 셀 선택 → 우측 Cell Z 편집 흐름에서 시선 앵커 제공.

### 2.5 F5 — 상단 클리핑 회피 (소규모)

- 라벨 칩의 화면상 y가 캔버스 상단(0) 미만이면 셀 **아래쪽**으로 플립. 좌측 음수도 0으로 클램프. (셀 로컬 계산만으로 판정 가능 — 뷰포트 변환은 이미 `getVisibleLocalBounds` 인프라 존재)

### 채택하지 않은 대안

| 대안 | 기각 사유 |
|---|---|
| 완전 scene 추종(라벨이 도형과 1:1로 커짐) | 축소 시 소멸(과거 버그 재현), 초확대 시 라벨이 화면 점유. 클램프형이 상위 호환 |
| DOM 오버레이(HTML 라벨) | 셀 수천 개 DOM 노드 → Flyweight 설계 취지 붕괴. 캔버스 직접 그리기 유지 |
| 라벨 크기 사용자 설정 추가 | 설정 항목 증가 대비 이득 낮음 — 클램프 기본값으로 충분. 필요 시 후속 |

## 4. 검증 계획 (리빌드 후 실기)

1. **줌 스윕**: 40% → 100% → 200% → 600%+ 에서 라벨이 11→22px로 연속 확대 후 고정되는지, 축소 시 11px 미만으로 작아지지 않는지.
2. **대비**: 카메라 영상의 밝은/어두운 영역, 도형 선 위에 겹친 상태 각각에서 칩 덕분에 판독 가능한지.
3. **LOD**: 100×100 매트릭스 축소 상태에서 라벨 뭉침 없음((0,0)만 표시), 확대하면 피치 임계 통과 시점부터 개별 라벨 출현. 팬/줌 FPS 저하 없음.
4. **활성 셀**: 셀 클릭 시 해당 라벨 강조(반전 칩), 다른 셀과 즉시 구분. 선택 해제 시 원복.
5. **클리핑**: 최상단 행이 화면 상단에 붙었을 때 라벨이 아래로 플립되어 잘리지 않는지.
6. **회귀**: MatrixDisplayIssues2 §4 시나리오(편집↔가공 반복 라벨 정합, 확대 시 표시 유지) 재확인. Show numbering & Z-info OFF 시 전부 비표시. `tsc` 신규 오류 0건.
